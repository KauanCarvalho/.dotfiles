## Preferences
- Keep code simple, no over-engineering, no unnecessary abstractions.
- Prefer editing existing files/reusing existing helpers over new ones.
- No unnecessary comments or docstrings.
- Semantic commit messages (feat/fix/docs/refactor/chore).

## Workflow
- Consult before big or risky changes, don't just proceed.
- Verify claims by actually running/testing, not assuming.
- Stop and report if blocked, don't guess past it.

## Style
- Terse, direct, no filler.
- Docs: plain and factual, no dashes, no justification/history prose.
